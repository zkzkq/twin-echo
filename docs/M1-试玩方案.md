# M1 试玩方案（15 人验证 H1）

> 目的：跑通 GDD §12.2 的 M1 Exit Criteria，并回收 §14 的埋点 KPI。
> 本方案的核心是**不解释、只观察**——H1 假设是"走位编队 + 共鸣能在 30 秒内被新玩家本能理解"，
> 任何口头解释都会污染结论。

## 0. 准备（5 分钟）

1. 启动：`pnpm dev`（默认 http://127.0.0.1:4173 ）。若要给多人试玩，每人一台机器 / 或用 `--host 0.0.0.0` 让同局域网访问。
2. **每位测试者用独立浏览器窗口**（或先清一次站点数据），保证 `firstRun=true`：这样才能拿到"首局前 90s 生成 ×0.5 + 首局免费复活"的真实新手体验。
3. 确认结算页右下角有「导出遥测 CSV」按钮（没有说明跑的是旧版本）。
4. 试玩结束后把 CSV 收进 `telemetry/` 目录，跑 `node scripts/summarize-telemetry.mjs telemetry` 得到汇总。

## 1. 试玩脚本（每人约 20–30 分钟）

| 阶段 | 内容 | 主持者做什么 |
|---|---|---|
| 开场（1min） | 只说一句："这是一款割草游戏，用 WASD 移动，活到 10 分钟。" **不提残影、不提共鸣、不提空格** | 不补充、不提示 |
| 第 1 局（≤10min） | 自由玩 | 记录：是否在第 1 分钟内自己发现"青色残影在重演我"；何时第一次主动利用残影；卡在哪 |
| 访谈 A（3min） | ①"你注意到场上还有另一个'你'吗？它是什么？" ②"你觉得你的走位和输出有关系吗？" ③"共鸣击（那个双色火花）你注意到了吗？" | 只记录原话，不纠正 |
| 第 2–3 局（≤20min） | 自由玩（可按 R 重开） | 记录是否换构筑、是否用空格爆发、是否抱怨难度/无聊 |
| 访谈 B（5min） | 按下面量表打分 | 逐项记录 |

## 2. 需要填的量表（逐人一份）

**共鸣机制体验（H1 核心）**

- 共鸣机制 fun 评分：1 / 2 / 3 / 4 / 5 （**≥3/5 才算通过**；1=完全无感，5=想主动研究）
- "你是否理解为什么有时伤害更高？" 是 / 否 / 说不清
- "你走过的地方会留下残影，这件事你什么时候意识到的？" （分钟数或"没意识到"）
- 主观难度：太难 / 偏难 / 刚好 / 偏易 / 太易
- **"想再来一把"**：想 / 不确定 / 不想（**≥10/15 人"想"才算通过**）

**开放题**

- 最爽的瞬间是什么？
- 最烦/最困惑的是什么？
- 如果只改一件事，改什么？

## 3. 自动 KPI（由 CSV 汇总，无需人工记录）

`node scripts/summarize-telemetry.mjs telemetry` 会输出：

| KPI | 门槛（§14 / §7.6） | 说明 |
|---|---|---|
| 人均局数 | ≥2 | M1 Exit Criteria |
| 存活中位时间 | §14 目标 ≥11min（20min 局）；**10min MVP 局建议 ≥6min** | 机器人下限 3.2–4.9min，人类应显著更高 |
| 终局等级中位 | MVP ≈26@10min | §7 拍点表 |
| 共鸣覆盖率 | 30–45% | **已知风险：实测 8–20%**，详见调参记录发现 3 |
| 升级跳过率 | <8% | §14 报警线 >15% |
| 爆发间隔 | 60–90s | §5.3 |
| 死亡点热区 | — | 判断"被围死"还是"跑位失误"（§7.6 被围死占比 <35%） |

## 4. 判定与后续动作

- **通过**：≥10/15 想再来 + 共鸣 fun ≥3/5 + 人均 ≥2 局 → 进 M2 垂直切片。
- **部分通过**：fun ≥3 但覆盖率低（<20%）→ 先执行共鸣几何 A/B 结论（`pnpm ab` 输出）再进 M2。
- **未通过**（fun <3 且两轮迭代无改善）→ 触发 GDD §12.2 Kill Criteria：冻结内容生产，按备选方案把残影降级为可选升级，回归"机制扎实的品类作品"。

## 5. 观察者注意事项

- 区分**观察**（"他连续 3 次斜向穿怪"）与**解读**（"他在用残影补刀"），分开记录。
- 不要替测试者按键，不要在他死亡时安慰性解释机制。
- 首局若在 5 分钟内死亡，会触发免费复活（§9）——**不要提前告知**，观察他是否理解发生了什么。
- 记下所有崩溃/卡顿：崩溃率 <0.5% 是 M3 门槛，早发现早修。
